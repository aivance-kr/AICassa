# 개발 속도 개선 가이드

> 이슈 1개당 개발 시간의 최대 병목이던 **검증·CI 왕복**을 없애기 위한 로컬 자동화 정리.
> 관련 변경: PR #47(개발 속도 개선), 반영 완료(dev·main). 상세 훅 문서는 [`.githooks/README.md`](../.githooks/README.md).

## 1. 왜 느렸나 (진단)

이슈 1개당 30–60분 중 가장 시간이 새던 구간은 **검증·CI 왕복**이었다.

```
코드 작성 → push → GitHub Actions(3~5분) → CS/PHPStan/PHPUnit 실패 발견 → 수정 → 다시 push …
```

CI 왕복 1회 = **3~5분 + 컨텍스트 전환 비용**. 이슈당 2~3회만 돌아도 10~20분이 증발한다.
그런데 로컬(PHP·Composer·MySQL 있는 환경)에서 **동일한 CI 게이트를 ~66초에 재현**할 수 있다.
결론: 검증을 로컬에서 **push 전에** 끝내면 왕복이 사라진다.

## 2. 무엇이 바뀌었나

### (1) Git 훅 — 실패를 커밋·push 시점에 자동 차단
| 훅 | 동작 | 막아주는 것 |
|----|------|------------|
| `pre-commit` | 스테이징된 `*.php` 를 PHP CS Fixer 로 자동수정 후 재-스테이징 | CS 위반이 CI 에서야 터지는 왕복 |
| `pre-push` | `composer check`(CS·PHPStan·PHPUnit) 실행, 실패 시 push 중단 | red 상태로 CI 로 넘어가는 것 |

### (2) 테스트 스위트 분리 (`phpunit.dist.xml`)
- `unit` — DB 불필요, 순수 로직. 개발 중 즉시 실행용.
- `feature` — DB·마이그레이션·HTTP 흐름. DB 를 타는 서비스 테스트(`DepreciationServiceTest`·`VatCalculatorServiceTest`)도 여기 포함.
- 기본 실행(`composer test`)은 두 스위트 전체 = **CI 와 동일**(185 tests).

### (3) 빠른 검증 스크립트 (`composer.json`)
| 명령 | 내용 | 용도 |
|------|------|------|
| `composer test:unit` | 유닛 스위트만, 커버리지 제외 | 개발 중 즉시 피드백 |
| `composer test:fast` | 전체, 커버리지 제외 | 커밋 전 빠른 확인 |
| `composer check:fast` | CS → PHPStan → 유닛 | 빠른 로컬 게이트(feature 제외) |
| `composer check` | CS → PHPStan → 전체 PHPUnit | **push 전 CI 패리티** |

## 3. 효과 (실측)

| 검증 | 명령 | 소요 |
|------|------|------|
| 개발 중 즉시 | `composer test:unit` | **~0.8초** (37 tests, DB 불필요) |
| 커밋 전 전체 | `composer test:fast` | ~60초 |
| push 전 CI 패리티 | `composer check` | **~66초** |
| (기존) CI 왕복 1회 | GitHub Actions | 3~5분 + 컨텍스트 전환 |

## 4. 팀원 셋업 (클론당 최초 1회)

```bash
git pull
composer install
composer hooks:install     # pre-commit·pre-push 훅 활성화(core.hooksPath=.githooks)
```

확인:
```bash
git config core.hooksPath   # → .githooks 면 활성
```

## 5. 일상 워크플로우

```
개발 중   → composer test:unit      # <1초, 즉시 피드백
커밋      → (pre-commit) CS 자동교정
push      → (pre-push) composer check 강제 → 실패면 자동 차단
```

- 포맷만 문제면: `composer cs-fix`
- 마이그레이션 필요한 검증: `php spark migrate --all` (그냥 `migrate` 는 Shield `users` 테이블 누락으로 FK 실패)
- 긴급 우회(WIP 백업 push 등): `SKIP_HOOKS=1 git commit …` / `SKIP_HOOKS=1 git push …`

> PHP·Composer 가 없는 Windows 체크아웃이라면 검증은 WSL 클론에서 수행한다(상세는 [CLAUDE.md](../CLAUDE.md) › 로컬 검증 선행).

## 6. 배포(CD) 참고

- `dev → main` 배포는 **merge commit**(Squash 금지 — main 을 dev 조상으로 유지, fast-forward 무충돌).
- 현재 CD(SSH 배포)는 **실서버 부재로 비활성화**(`disabled_manually`) 상태. 서버 준비 시 `production` 환경에 배포 secret 5종 등록 후 `gh workflow enable deploy.yml`.
